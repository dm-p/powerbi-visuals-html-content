# Edition selection relies on git-ignored generated files

## Context

The visual ships in multiple editions (certified / standard / standalone). Which
sanitizer backend gets compiled is chosen at build time by
`scripts/select-edition.mjs`, which writes two **git-ignored** files:

- `src/sanitize/backend.ts` — re-exports the selected backend (`backend.certified` or `backend.passthrough`)
- `config/active-edition.mjs` — the active edition name that `pbiviz.mjs` reads

These are generated by the `postinstall` hook and the `prestart`/`pretest` presteps.
Because they are git-ignored, they exist only after a lifecycle script has run.
Any workflow that skips lifecycle scripts leaves them absent.

## Guidance

Two durable points came out of a code review of this mechanism:

1. **The generated files are a bootstrap requirement, not an optimization.**
   If you install with `--ignore-scripts` (`npm install`/`npm ci --ignore-scripts`)
   or invoke a bundler directly, run the prestep once before compiling:

   ```bash
   node scripts/select-edition.mjs certified
   ```

   Without it, compilation fails with a confusing `Cannot find module './backend'`
   TypeScript error rather than anything pointing at the missing prestep. This is
   documented in AGENTS.md's Setup section so a fresh contributor can self-serve.

2. **Lean-bundle verification must cover every passthrough edition.** Both
   `standard` and `standalone` share the dependency-free passthrough backend and
   should produce sanitizer-free bundles. `scripts/check-no-sanitizer.mjs` greps the
   built bundle for sanitizer fingerprints (`dompurify`, `postcss-value-parser`). It
   takes the bundle path as `argv[2]` (default `.tmp/drop/visual.js`), so one checker
   serves every edition — give each lean edition its own `verify-*-lean` npm script
   rather than verifying only one and assuming the other is fine.

## Why This Matters

The generated-file pattern keeps the sanitizer subtree out of base-edition bundles
(measured ~93KB / 20% reduction) via tree-shaking. The cost is a hidden dependency
on a lifecycle script: the failure mode (`Cannot find module './backend'`) gives no
hint that a prestep was skipped, so a contributor can lose time chasing a phantom
TypeScript/path problem. Likewise, verifying only `standalone` leaves a silent gap —
a stray sanitizer import in the `standard` build config would go undetected until
someone happened to exercise the `standalone` path.

## When to Apply

- Before bundling/compiling outside the normal `npm` lifecycle (CI with `--ignore-scripts`, raw `tsc`/webpack, fresh clones)
- When adding a new edition — wire both its `package-*` and a `verify-*-lean` script
- When `Cannot find module './backend'` appears — run the prestep, don't debug the import

## Examples

Parameterized checker reused across editions:

```js
// scripts/check-no-sanitizer.mjs
const BUNDLE = process.argv[2] ?? '.tmp/drop/visual.js';
```

```json
// package.json — one verify script per lean edition, same checker
"verify-standalone-lean": "npm run package-standalone && node scripts/check-no-sanitizer.mjs",
"verify-standard-lean":   "npm run package-standard && node scripts/check-no-sanitizer.mjs"
```
